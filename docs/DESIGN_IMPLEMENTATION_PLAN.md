## 修复的问题

- 五个导航此前只是滚动或跳往旧界面，现在有独立 URL 和一致布局。
- 收藏修改后页面统计不一致：统一刷新数据源。
- 图鉴只有截断列表：增加加载更多；首页预览保留完整图鉴入口，不显示无效分页。
- 未录入版本的专辑以前容易被理解为缺少收藏：明确区分“待录入版本”和实际“待补版本”。
- 编辑自定义发行类型丢失：类型字段支持原值与自由输入。
- 旧缺失／心愿 PWA 链接保留兼容。
- JSON 备份缺少曲目、标记：完整导出恢复，并加入个人资料；无效恢复由测试验证不清空原数据。
- 预置脚本与服务端的 `.env` 数据库配置不一致：统一加载。
- 头像／封面缺失时显示柔和占位，图片失败可降级。
- 手机窄屏的胶带装饰越界：限制在照片范围内。

## 数据与素材边界

- 高清基准现为 `originals/01-home.png` 至 `05-about-me.png`。旧 WebP 为缩略图，其中 `reference-style.webp` 曾损坏；保留历史文件但不再作为验收依据。
- 正式库保留原有收藏，不导入截图中的 128、50 等示例数量，不虚构价格、团体或收藏成就。
- 预置目录仅 32 个发行、291 首曲目，没有预置实体版本。收藏和心愿空白是准确状态，需手动录入或后续核实目录再导入。
- 收藏角照片由 imagegen 新生成；实际专辑封面仍用原目录来源。可在关于我上传自己的团体照片作为主视觉。
- 底部播放器可播放专辑子页上传的本地音频；未接入第三方音频服务。
- 备份数据库或 JSON 时，请另备份 `public/uploads`；数据库不内嵌图片。

## 验证方式

`npm run check` 通过；`npm test` 24 项通过。自动测试包含目录导入幂等、profile 校验和保存、library 数据完整性、CRUD、JSON 新旧备份及事务回滚、SQLite 导出恢复及无效文件保护，以及前端路由、筛选、统计、空状态、分页和文本转义。

浏览器使用独立测试库验证新增心愿版本、标记已收到、个人资料和头像上传、刷新保持、搜索、加载全部 32 张、网格／列表、前进后退、备份入口；检查 1440px／1536px 桌面、820px 平板、390px 手机。正式收藏库不用于破坏性恢复测试。
